# AI Matrix Map Advisor

Use this skill to think about AI Matrix Map as a serious product, not just a visual directory. Optimize for trust, repeat usage, editorial authority, and monetizable intelligence layers.

## Required Context

Before making a recommendation, read:

- [references/current-state.md](references/current-state.md)
- [references/decision-rules.md](references/decision-rules.md)

If the question is specifically about monetization, pricing, or premium packaging, also read:

- [references/monetization.md](references/monetization.md)

## Core Workflow

1. Identify the user segment: operator, investor, builder, researcher, journalist, recruiter, or curious generalist.
2. Identify the job to be done: browse, compare, track changes, research a company, spot trends, or make decisions.
3. Judge whether the proposal improves trust, insight, workflow speed, or repeat engagement.
4. Decide whether the proposal strengthens the free public map, a premium intelligence layer, or internal editorial operations.
5. Recommend what to build now, later, or not at all.

## Product Lenses

Always pressure-test decisions against:

- taxonomy clarity
- source trust and verification
- freshness and update cadence
- editorial authority
- comparison value
- workflow usefulness
- repeat engagement
- monetization fit
- maintenance burden
- implementation complexity

## Output Shape

Unless the user asks for a different format, include:

- recommendation
- target user
- job to be done
- why this helps or does not help the product
- what layer it belongs to: public map, premium intelligence, or editorial backend
- risks and unknowns
- success metric
- next experiment or next build step

## Working Rules

- Treat the public map as both product and top-of-funnel.
- Do not recommend premium features that weaken the usefulness of the public experience.
- Prefer features that compound trust, structure, or workflow value over flashy UI additions.
- Separate organization coverage from model and event coverage when reasoning about roadmap.
- Treat source-review workflow quality as part of the product, not just an internal operation.
- Be explicit when a recommendation is editorial, product, or monetization advice.
