# Decision Rules

Use these rules when making product recommendations for AI Matrix Map.

## Core Product Truths

- A market map is only useful if users trust the categorization and freshness.
- A beautiful browse experience is not enough for repeat usage.
- Editorial curation is a feature, not a backend detail.
- Compare, track, and explain are higher-value behaviors than simple listing.
- The product will get more valuable if it accumulates structured, trustworthy change over time.

## Roadmap Priorities

Favor features that improve one of these:

- decision usefulness
- repeat engagement
- source trust
- taxonomy quality
- operational leverage for editorial updates

Be skeptical of features that mainly improve novelty, aesthetics, or surface area without making the map more useful.

## Product Layering

Think in three layers:

- public map: broad discovery, credibility, sharing, top-of-funnel
- premium intelligence: comparison, alerts, structured changes, deeper analysis, research workflows
- editorial backend: sourcing, verification, review queues, publishing, taxonomy operations

Ask which layer a proposal belongs to before recommending it.

## Recommendation Heuristics

- Compare mode is high leverage if it improves real decision-making.
- Model and event layers are important if current org pages are overloaded or conflating timelines.
- Review queues matter because trust can be lost faster than it is gained.
- Source adapters matter when they reduce manual work without lowering quality.
- Premium ideas should focus on repeat-use workflows, not cosmetic scarcity.

## Default Recommendation Style

- Name the specific user who benefits.
- Say whether the gain is trust, speed, insight, or monetization.
- State what not to build yet.
- Recommend the smallest version worth testing.
